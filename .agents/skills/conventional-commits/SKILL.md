# Conventional Commits для HHRaiser

## Обязательный формат

```text
<type>(<scope>): <краткое описание на русском языке>
```

`scope` необязателен. Описание пишется со строчной буквы, в повелительной форме,
без точки в конце. Технический `type` остаётся английским согласно Conventional
Commits, остальной текст — русский.

Допустимые типы:

- `feat` — новая пользовательская возможность;
- `fix` — исправление ошибки;
- `docs` — только документация;
- `test` — тесты без изменения production-поведения;
- `refactor` — изменение структуры без новой возможности или исправления;
- `perf` — повышение производительности;
- `build` — сборка или зависимости;
- `ci` — CI/CD;
- `chore` — служебное изменение, не подходящее под другие типы.

## Рабочий процесс

1. Прочитать `git status` и весь релевантный diff.
2. Не включать пользовательские или несвязанные изменения.
3. Проверить отсутствие credentials, профиля браузера, cookies, токенов и логов с
   персональными данными.
4. Выполнить проверки, соразмерные изменению.
5. Создать один логически цельный коммит. Разделить независимые изменения.
6. Проверить сообщение по формату до выполнения `git commit`.
7. По умолчанию работать с `main` репозитория HHRaiser и отправлять в `origin/main`,
   если пользователь не указал другую ветку.

Не переписывать историю, не выполнять amend, rebase или force-push без явного
разрешения пользователя.

## Примеры

```text
feat(config): добавить пользовательские поисковые запросы
fix(browser): завершать процесс после закрытия окна
docs(readme): упростить запуск полного режима
test(logging): проверить сводку просмотра вакансий
refactor(activity): вынести ротацию выдачи в отдельный сервис
```

Для несовместимого изменения использовать `!` и русское пояснение:

```text
feat(config)!: изменить формат файла настроек

BREAKING CHANGE: секция [search] заменена секцией [activity].
```
