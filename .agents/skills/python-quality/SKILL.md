# Качественный Python-код для HHRaiser

## Базовые правила

- Поддерживать Python 3.12 и настройки `pyproject.toml`.
- Сохранять обратную совместимость `hh_resume_raiser.py` и существующего CLI без
  явного решения пользователя об обратном.
- Использовать `from __future__ import annotations`, точные type hints, `pathlib`,
  `dataclass` и `StrEnum`, когда они делают модель яснее.
- Давать функциям одну ответственность, избегать скрытого глобального состояния и
  дублирования логики.
- Предпочитать ранние возвраты глубокой вложенности.
- Не создавать абстракции без реального повторного использования или границы слоя.
- Соблюдать лимит строки Ruff в 100 символов.

## Архитектурные границы

- `domain/` не зависит от Playwright и инфраструктуры.
- `application/` координирует сценарии и политики.
- `activities/` реализует одно наблюдаемое пользовательское действие.
- `infrastructure/` содержит Playwright, локаторы, HH-адаптеры и хранение.
- `reporting/` отвечает за обезличенные события и сводки.
- Пользовательские значения — название резюме, профессия, запросы и интервалы — не
  зашивать в код; получать их из CLI, окружения или локального INI.

## Playwright и надёжность

- Приоритет локаторов: ARIA role и accessible name, label, видимый текст,
  стабильный `data-qa`, затем CSS.
- Не использовать координаты, `nth-child`, нестабильные классы и хрупкие XPath,
  если доступна семантическая альтернатива.
- Подтверждать действие наблюдаемым состоянием интерфейса; сеть использовать лишь
  как дополнительный сигнал.
- Различать `success`, `skipped`, `error` и `unknown outcome`.
- Не повторять автоматически действие с неизвестным исходом, если повтор может
  продублировать изменение.
- Закрытие страницы или браузера немедленно передавать основному циклу.
- Не блокировать обработку событий Playwright длительным обычным `sleep`.
- Рекламные модальные окна закрывать централизованным modal guard.

## Безопасность и данные

- Не записывать cookies, пароли, Authorization headers, session tokens, приватные
  сообщения, содержимое резюме или полные сетевые тела.
- Очищать URL от query-параметров и идентификаторов перед журналированием.
- Хранить профиль, credentials, локальное состояние, traces и исследовательские
  артефакты только в каталогах, исключённых из Git.
- Нормализовать внешние строки перед логированием, чтобы переносы строк не ломали
  формат журнала.

## Ошибки и журналирование

- Ловить только ожидаемые исключения и сохранять исходную причину через `raise ...
  from error`, когда создаётся новое исключение.
- Не маскировать `KeyboardInterrupt` и ошибки закрытого Playwright target.
- Писать сообщения, объясняющие событие и следующий шаг пользователя.
- Не создавать повторяющиеся INFO-сообщения; для серий действий выводить понятную
  сводку, сохраняя подробные обезличенные события для аналитики.

## Проверка изменения

Добавлять тест на исправленную ошибку или новую ветвь поведения. Изолировать
чистую логику от браузера, чтобы её можно было тестировать без HH и сети.

Перед коммитом выполнить:

```powershell
.\.venv\Scripts\ruff.exe format hh_raiser tests
.\.venv\Scripts\ruff.exe check hh_raiser tests
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
git diff --check
```

Если изменение затрагивает реальный UI HH, дополнительно проверить его в видимом
браузере и не сохранять исследовательские данные в Git.
