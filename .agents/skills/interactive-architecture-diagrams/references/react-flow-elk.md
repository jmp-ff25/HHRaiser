# React Flow + ELK: практический профиль

## Модель узла

Минимально полезная модель содержит:

```text
id, title, summary, kind, phase, responsibility
preconditions, success, unknown, failures, retry
configKeys, codeLinks, tags
```

`title` и `summary` остаются короткими для canvas. Подробное содержание выводится
в инспекторе и не влияет на размер узла.

## Профиль ELK Layered

Начальная конфигурация для горизонтального процесса:

```text
elk.algorithm = layered
elk.direction = RIGHT
elk.edgeRouting = ORTHOGONAL
elk.layered.crossingMinimization.strategy = LAYER_SWEEP
elk.layered.nodePlacement.strategy = NETWORK_SIMPLEX
elk.layered.wrapping.strategy = MULTI_EDGE
```

Подбирай расстояния после рендера реального текста. Циклические связи допускаются,
но для длинных процессов включай graph wrapping и подбирай `elk.aspectRatio` под
рабочую область. Если обратная связь всё равно разрушает карту, показывай её как
переход между представлениями.

## Интерактивность

- Один клик выбирает узел и синхронизирует постоянный инспектор.
- Клик по пустому пространству снимает выбор.
- URL/hash сохраняет активное представление и выбранный узел.
- Поиск приглушает несовпадающие элементы, не перестраивая граф.
- На узком экране инспектор становится закрываемой панелью поверх canvas.
- Учитывай `prefers-reduced-motion` и обеспечивай заметный `focus-visible`.

## Автономная поставка

Не подключай пакеты через CDN. Для открытия через `file://` используй production-
сборку с относительными или встроенными ресурсами. Оставляй loading shell в HTML,
а canvas показывай только после завершения ELK layout.

## Визуальная приёмка

Проверь как минимум:

- широкое окно около 1440×900;
- среднее окно около 1024×768;
- узкое окно около 390×844;
- все представления, правую панель и длинные русские подписи;
- отсутствие горизонтальной прокрутки страницы;
- fit-to-view, поиск, тему, мини-карту и закрытие мобильной панели;
- консоль браузера без ошибок;
- автономный production-файл после отключения сети.

Скриншот считается проверкой только вместе с осмотром границ, текста, стрелок и
состояния выбранного элемента. Успешная сборка не заменяет визуальную приёмку.
