# HHRaiser

**Локальный менеджер активности и актуальности личного резюме на HH.ru**

![Python](https://img.shields.io/badge/Python-3.12%2B-3776AB?logo=python&logoColor=white)
![Playwright](https://img.shields.io/badge/Playwright-1.62%2B-2EAD33?logo=playwright&logoColor=white)
![Status](https://img.shields.io/badge/status-experimental-orange)

Разработка и сопровождение: [jmp-ff25](https://github.com/jmp-ff25)

</div>

HHRaiser автоматизирует разрешённые действия владельца личного резюме: проверяет
доступность поднятия, просматривает настраиваемую выдачу вакансий, контролирует структуру
резюме и, при явном включении, отправляет только простые отклики без обязательных форм.
Приложение работает локально через
Playwright и постоянный профиль Chromium; архитектура разделена на доменный,
прикладной и инфраструктурный слои для дальнейшего переноса на сервер.

> Автоматические отклики по умолчанию выключены. Проект не заполняет анкеты, тесты,
> обязательные сопроводительные письма и внешние формы, а также не обещает повышения
> позиции резюме или вероятности трудоустройства.

## Быстрый старт

Ниже — короткий путь от клонирования до первого запуска на Windows, Linux и macOS.

> `Task` — единственный инструмент, который устанавливает владелец для локальной
> работы. Скрипты установки сами устанавливают `uv`, Python и зависимости. Node.js
> не требуется.

### 1. Установите проект

```text
git clone git@github.com:jmp-ff25/HHRaiser.git
cd HHRaiser
task setup
```

> Кэш `uv` хранится в `.uv-cache` внутри каталога проекта на любой платформе и
> исключён из Git. Его можно удалить: нужные данные будут загружены при следующем
> запуске.
>
> Chromium Playwright также устанавливается локально: в
> `state/main/playwright-browsers`. Установщик и приложение используют один и
> тот же каталог.

Команда создаёт `.venv` через `uv`, устанавливает приложение и Chromium, а затем
копирует шаблон в `state/main/hh-config.ini`, только если локальной конфигурации ещё
нет. После этого она проверяет, что обязательные значения уже заполнены, не запрашивая
секреты в терминале. Каталог `state/main` — единое локальное состояние основного экземпляра: в нём
лежат конфиг, профиль браузера, SQLite, статус и Excel-отчёт; он исключён из Git.

Если `uv` ещё не установлен, вместо `task setup` используйте один из bootstrap-скриптов:

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
```

```bash
# Linux и macOS
./scripts/setup.sh
```

Они устанавливают `uv`, зависимости и Chromium, но завершаются с ошибкой, если `.env`
или `state/main/hh-config.ini` отсутствуют либо содержат незаполненные обязательные поля.

### Сервер Debian/Ubuntu

После клонирования проекта, заполнения `.env` и `state/main/hh-config.ini` выполните:

```bash
sudo ./scripts/install-ubuntu.sh
uv run hhraiser start
```

Установщик сам получает `uv`, Python-зависимости и Chromium, проверяет конфигурацию,
а затем регистрирует две systemd-службы: основной экземпляр и Telegram-бота. Секреты
не выводятся и не запрашиваются. Дальнейшее управление на сервере:

```bash
uv run hhraiser status
uv run hhraiser logs --lines 100
uv run hhraiser stop
uv run hhraiser update
uv run hhraiser reconfigure
```

Файлы проекта, включая `.env`, `state/`, виртуальную среду и Chromium, остаются внутри
каталога HHRaiser. Systemd-unit-файлы удаляются отдельно при деинсталляции; удалить
папку проекта во время работы службы нельзя — сначала выполните `uv run hhraiser stop`.

### 2. Заполните настройки и учётные данные

После установки в `state/main` появится `hh-config.ini` с комментариями ко всем
настройкам. Его можно редактировать по SSH или через Telegram-бота — это один и тот
же файл. Укажите в нём название резюме и поисковые запросы. Например:

```ini
[resume]
# Точное название резюме на HH.ru.
title = Точное название моего резюме

[activity]
# Поисковые запросы: одно значение на строку.
search_queries =
    Первый поисковый запрос
    Второй поисковый запрос
# Максимальный размер одной группы вакансий.
vacancies_per_group = 5
# Максимум страниц выдачи за цикл: от 1 до 200.
search_pages_per_cycle = 25
# Максимум новых вакансий в истории за цикл: от 0 до 100000.
unique_vacancy_limit = 1000
# Через сколько дней вакансию можно снова считать новой: от 0 до 3650.
revisit_after_days = 14
# Начинать новый обход после исчерпания очереди страниц.
reset_on_exhaustion = true

[search_filters]
# Слова, которые исключаются из результатов: одно значение на строку.
excluded_words =
    senior
    аналитик
    тестировщик
# Поля поиска: name, company_name или description; пусто — стандартное поведение HH.
search_fields =
    name
# Уровни опыта: noExperience, between1And3, between3And6 или moreThan6.
experience =
    between1And3
    between3And6
# Регионы: одно название на строку; пусто — все регионы.
areas =
    Москва

[matching]
# Проверять соответствие вакансии резюме до возможного отклика.
enabled = true
# Минимальная расчётная оценка для отклика: от 0 до 100.
threshold = 55

[responses]
# Разрешить простые отклики без обязательных форм.
enabled = false
# Максимум успешных откликов за московский день; 0 — без ограничения.
daily_limit = 0

# Автоматическое распознавание текстовых CAPTCHA через Gemini.
# После пяти неудачных попыток программа запросит ручной ответ в Telegram.
[captchasolution]
# Включите, чтобы автоматическое решение CAPTCHA работало в full-activity.
enabled = true
# Выполнять платный интеграционный тест Gemini при запуске тестов.
integration_test_enabled = false
# Секретный ключ Polza AI. Не добавляйте его в Git.
polza_api_key = ...
# Инструкция, отправляемая модели вместе с CAPTCHA.
ocr_prompt =
# Адрес совместимого API Polza AI.
api_url = https://polza.ai/api/v1
# Модель для распознавания CAPTCHA.
model = google/gemini-3.8-flash
```

Создайте рядом файл `hh-credentials.ini`:

```ini
[hh]
# Номер телефона учётной записи HH в международном формате.
phone = +70000000000
# Пароль учётной записи HH. Не публикуйте его и не добавляйте в Git.
password = replace-me
```

`hh-config.ini` и `hh-credentials.ini` исключены из Git. Не добавляйте в Git пароль,
токены, cookies или профиль Chromium.

### 3. Один раз инициализируйте сессию

```text
task init-session
```

Завершите вход, CAPTCHA или дополнительное подтверждение в открытом Chromium.

### 4. Выберите режим работы

#### Полный режим

```text
task full-activity
```

Эта команда включает автоматическое поднятие, циклический просмотр настроенной
выдачи, предварительный отбор и просмотр подходящих вакансий, проверку структуры
резюме, обратимое обновление его версии и безопасные простые отклики.
Остановить программу можно одним нажатием Ctrl+C.

`task full-activity-ui` запускает тот же режим в видимом Chromium. Обе команды по
умолчанию равнозначны `task full-activity-responses` и
`task full-activity-responses-ui` соответственно.

Если в `[captchasolution]` установлено `enabled = true`, оба режима автоматически
пытаются распознать текстовую CAPTCHA через Gemini до пяти раз. Если HH не принимает
ответы, программа переходит к обычному ручному подтверждению через Telegram.

#### Совместимые названия режима с откликами

Следующая команда сохранена для совместимости и выполняет тот же полный режим с
простыми откликами на успешно просмотренные подходящие вакансии:

```text
task full-activity-responses
```

Его видимый вариант — `task full-activity-responses-ui`. Низкоуровневый параметр,
который добавляет отклики к другому режиму, называется `--auto-respond`. Например:

```text
task full-activity -- --auto-respond
```

Анкета, тест, обязательное письмо, выбор резюме или внешний сайт приводят к пропуску
только текущего отклика. Причина попадает в журнал, после чего программа продолжает
со следующей вакансией.

Порог берётся из `matching.threshold` в `hh-config.ini` и определяет допуск
к автоматическому отклику. Сама вакансия просматривается при любой оценке.
Task-профили не подменяют эту настройку. Если параметр отсутствует, приложение
использует встроенное значение 55. Это объяснимая эвристическая оценка, а не
статистически подтверждённая вероятность успеха или трудоустройства.

## Возможности

- поднятие выбранного резюме только тогда, когда соответствующее действие доступно;
- распознавание следующего времени поднятия и ожидание по системным часам;
- защита от повторного нажатия локальным cooldown-маркером;
- последовательный циклический обход заданных владельцем поисковых запросов;
- серверная фильтрация HH по словам-исключениям, областям поиска и опыту;
- случайный порядок страниц внутри запроса и вакансий внутри страницы;
- деление страницы на сбалансированные группы с паузой между ними;
- постоянный SQLite-журнал терминальных результатов отклика;
- проверка журнала откликов по публичному ID до анализа вакансии;
- объяснимая оценка соответствия вакансии выбранному резюме;
- прокрутка и содержательный просмотр вакансии независимо от оценки;
- отображение названия каждой открытой вакансии и итоговой сводки цикла в журнале;
- опциональный безопасный отклик только после успешного просмотра подходящей вакансии;
- пропуск только текущего отклика при анкете, тесте, обязательном письме, выборе
  резюме, подтверждении входа или внешнем сайте с продолжением очереди вакансий;
- отдельный фильтруемый Excel-журнал успешных и требующих ручного участия откликов;
- проверка наличия основных разделов резюме и рекомендаций HH;
- опциональная обратимая смена версии описания опыта с подтверждением сохранения;
- автоматическое закрытие известного рекламного окна hh PRO;
- видимый и headless-режимы, одноразовый запуск и непрерывная работа;
- корректная остановка при Ctrl+C или закрытии окна браузера;
- обезличенный JSONL-журнал для последующей аналитики.

## Установка и обновления

Сейчас `task install` подготавливает Python 3.12, изолированное окружение,
зависимости приложения и Chromium. Вручную активировать `.venv` не нужно.

Для разработки используйте `task install-dev`. На некоторых минимальных Linux-системах
для Chromium могут понадобиться системные библиотеки: `task install-system-deps`.

Единый установщик и деинсталлятор ещё не реализованы. Его требования и этапы работ
зафиксированы в [плане установки](docs/installation-roadmap.md); README не выдаёт
планируемые возможности за уже доступные.

## Команды разработки

`Taskfile.yml` является единой оболочкой для локального запуска и CI. Одни и те же
команды используются в любом поддерживаемом терминале:

- `task install` — установить приложение и Chromium;
- `task init-session` — выполнить первичную авторизацию в видимом Chromium;
- `task raise` / `task raise-ui` — только поднятие в фоновом или видимом режиме;
- `task activity` / `task activity-ui` — поднятие и вакансии без смены версии резюме;
- `task activity-responses` / `task activity-responses-ui` — просмотр вакансий и
  простые отклики без обязательных форм;
- `task full-activity` / `task full-activity-ui` — все возможности, включая
  обратимую смену версии резюме и безопасные отклики;
- `task full-activity-responses` / `task full-activity-responses-ui` — совместимые
  названия того же полного режима с безопасными откликами;
- `task activity-once` / `task full-activity-once` — один видимый цикл;
- `task check` — линтер и все тесты;
- `task build` — собрать wheel и исходный архив;
- `task` — показать весь список с краткими пояснениями.

Профили Task выбирают только набор возможностей и не фиксируют порог соответствия
или интервалы. Настройки из `hh-config.ini` имеют приоритет перед встроенными
значениями приложения. Разовую настройку можно передать через исходный CLI после
`--`; она имеет приоритет перед INI:

```text
task full-activity -- --match-threshold 75 --activity-interval-seconds 600
```

Любые дополнительные параметры исходного CLI передаются после `--`:

```text
task full-activity -- --vacancies-per-group 5
```

Пути к локальным файлам также настраиваются переменными Task:

```text
task full-activity CONFIG_FILE=my-config.ini CREDENTIALS_FILE=my-credentials.ini
```

## Настройка профессии и запросов

Все настраиваемые значения и допустимые варианты описаны комментариями в
`hh-config.example.ini`, который `task install` копирует в локальный `hh-config.ini`.
Главные поля: `resume.title`, `activity.search_queries`, `search_filters`,
`matching` и `responses`. Название резюме должно в точности совпадать с заголовком
на HH.ru, а поисковые запросы записываются по одному на строку.

Путь можно изменить переменной Task `CONFIG_FILE`. Разовые значения можно передать
исходному CLI после `--`, не создавая INI-файл:

```text
task activity-ui -- --resume-title "Моё резюме" --search-query "Первый запрос" --search-query "Второй запрос"
```

Также поддерживаются `HH_RESUME_TITLE` и список `HH_SEARCH_QUERIES`, разделённый
символом `|`. Приоритет: CLI, переменные окружения, `hh-config.ini`.

## Поисковые фильтры HH

Секция `[search_filters]` применяется ко всем поисковым запросам. В ней можно
исключить слова, ограничить поля поиска, опыт и регионы; допустимые значения указаны
комментариями в `hh-config.ini`. Пустое поле не создаёт ограничение. Названия регионов
записываются по одному на строку и при запуске сверяются с актуальным справочником HH.
Неоднозначное или неизвестное название останавливает запуск, чтобы поиск случайно не
пошёл по всем регионам.

## Сопоставление вакансии с резюме

До прокрутки вакансии приложение читает доступные в DOM заголовок, описание и теги
навыков. Текст выбранного резюме читается только в память процесса и не сохраняется.
Затем рассчитывается объяснимая оценка от 0 до 100 на основе четырёх признаков:

- сходство названий по коэффициенту Дайса;
- BM25F-подобная релевантность с повышенным весом названия и тегов навыков;
- доля навыков вакансии, найденных в резюме;
- косинусная близость частотных векторов значимых терминов.

Признаки объединяются логистической функцией. Вакансия прокручивается при любой
оценке, но автоматический отклик допускается только при достижении
`matching.threshold`. Оценка без попытки отклика в SQLite не сохраняется.

Начальные коэффициенты являются инженерной политикой, поэтому число называется
расчётной оценкой совместимости, а не подтверждённой вероятностью. Персональная
калибровка станет возможна после накопления явных пользовательских отметок.

Фильтр можно временно отключить через `--no-vacancy-matching`, а порог разово
заменить, например, через `--match-threshold 60`. Параметр командной строки имеет
приоритет перед `matching.threshold` из INI. Полное обоснование и формулы находятся в
[ADR-0001](docs/adr/0001-explainable-vacancy-matching.md).

## Циклический обход вакансий и отклики

Приложение обходит поисковые запросы строго в порядке `activity.search_queries`.
Для каждого запроса оно сначала открывает первую страницу, определяет актуальное
число страниц пагинации, а затем перемешивает остальные страницы без повторов.
После последней страницы начинается следующий запрос; после последнего запроса —
новый полный обход с первого элемента списка.

На каждой странице собираются канонические ссылки вида `https://hh.ru/vacancy/ID`.
Повторяющиеся ссылки удаляются, оставшиеся перемешиваются и делятся на сбалансированные
группы. `vacancies_per_group = 5` означает желаемый максимальный размер группы:
девять вакансий будут разделены на `5 + 4`, а двенадцать — на `4 + 4 + 4`.
За один запуск активности обрабатывается одна группа. Следующая группа начинается
через полный `activity_interval_seconds` после завершения предыдущей; стандартное
значение — пять минут.

Измените паузу в `hh-config.ini`, например на десять минут:

```ini
[activity]
activity_interval_seconds = 600
```

Для каждой вакансии действия идут последовательно:

1. Из публичной ссылки извлекается ID и проверяется журнал откликов.
2. Если терминальный результат уже записан, вакансия открывается и прокручивается,
   но повторный анализ и отклик не выполняются.
3. Для новой вакансии вычисляется соответствие резюме. Вакансия просматривается
   независимо от оценки; порог управляет только допуском к автоматическому отклику.
4. При достижении порога выполняется безопасная попытка отклика. Анкета, тест,
   обязательное письмо или внешний сайт получают статус `manual_required`.
5. В SQLite и Excel сохраняются только терминальные исходы попытки: `sent`,
   `already_sent`, `manual_required` и `unknown`. Обычные просмотры,
   оценки ниже порога, отсутствие кнопки и технические ошибки в БД не фиксируются.

После перезапуска обход страниц начинается с первого запроса, поскольку очередь
страниц и групп хранится только в памяти. Журнал терминальных откликов сохраняется,
поэтому повторная отправка исключается даже после переустановки процесса с прежней
базой данных.

Автоподнятие резюме и обход вакансий имеют независимые сроки в общем планировщике.
Один браузерный профиль не используется одновременно двумя потоками: перед каждой
группой основной цикл отдельно проверяет доступность поднятия, а следующая группа
ждёт свой полный интервал.

## Интерактивная схема бизнес-логики

Основная [интерактивная карта архитектуры](docs/architecture-viewer/index.html)
показывает жизненный цикл приложения, отбор вакансий, исключение повторных
просмотров и границы компонентов. Нажатие на любой элемент открывает постоянную
панель с ответственностью, предусловиями, успешным и неизвестным исходами,
настройками и ссылками на соответствующий код или ADR.

Карта построена на React Flow. Представления разделены на пронумерованные смысловые
ряды: читать сверху вниз, внутри ряда — слева направо. ELK.js раскладывает каждый ряд
отдельно. Короткие стрелки показывают соседние шаги, а подписанные кнопки внутри блоков
заменяют длинные связи и возвраты. Нажатие на переход перемещает к целевому блоку и
открывает его описание. В представлении «Компоненты» связи означают использование
модулей, а не порядок выполнения.
Доступны поиск, масштабирование, мини-карта, светлая и тёмная темы, четыре уровня
детализации и ссылки на выбранный элемент в URL. Production-сборка содержит все
зависимости внутри одного HTML-файла, не использует CDN и работает без интернета.
Откройте `docs/architecture-viewer/index.html` любым современным браузером.

Node.js и локальный веб-сервер для обычного просмотра не требуются. Адрес вида
`http://127.0.0.1:5173` появляется только в режиме разработки, когда изменения
исходников нужно видеть сразу после сохранения. Такой процесс работает, пока открыт
запустивший его терминал, и останавливается сочетанием `Ctrl+C`.

Для изменения карты сначала установите её зависимости, затем запустите режим
разработки:

```text
task diagram-install
task diagram-dev
```

После запуска `task diagram-dev` откройте адрес, который Vite напечатает в
терминале. Этот режим необязателен и предназначен только для разработки карты.

После изменений проверьте модель и пересоберите автономный файл:

```text
task diagram-check
```

Предыдущая [интерактивная блок-схема](docs/business-logic.html) сохранена для
сравнения. Для разработчиков также доступны две компактные схемы PlantUML:
[обзор непрерывного цикла](docs/diagrams/overview.svg) и
[детальный отбор вакансий](docs/diagrams/vacancy-flow.svg). Исходники PlantUML
находятся рядом в каталоге `docs/diagrams`.

## Режимы запуска

### Только автоматическое поднятие резюме

Непрерывный headless-режим без индекса активности:

```text
task raise
```

Для видимого Chromium используйте `task raise-ui`; окно автоматически развернётся
по доступной области монитора.

### Однократная безопасная проверка

```text
task init-session
```

### Один полный цикл просмотра

```text
task activity-once
```

### Непрерывное поднятие и просмотр вакансий

```text
task activity
```

`--vacancies-per-group` задаёт желаемый максимальный размер одной группы.
После группы выдерживается `--activity-interval-seconds`; общий обход запросов
и страниц не ограничен.

### Полный режим с обратимым обновлением версии резюме

```text
task full-activity
```

Этот режим выключен по умолчанию. Первый цикл выполняется сразу: приложение
последовательно выбирает опыт и добавляет одну контрольную точку. На следующем
цикле точка удаляется из того же опыта, сохранение подтверждается повторным чтением
интерфейса, после чего выбирается следующий опыт. Содержимое описания не хранится
в служебных файлах — сохраняются только номер опыта, исходное число конечных точек
и контрольная сумма нормализованного текста.

## Безопасные отклики и Excel-журнал

`full-activity` включает безопасные отклики по умолчанию. Их можно явно включить
или отключить настройкой:

```ini
[responses]
enabled = true
daily_limit = 25
```

Значение `daily_limit = 15` без строки `enabled` также включает отклики; добавьте
`enabled = false`, если хотите оставить только просмотры.

`daily_limit` считает только подтверждённые успешные отклики за календарный день по
московскому времени. Анкеты, тесты, ручные действия и технические ошибки лимит не
расходуют. Значение `0` означает отсутствие дневного ограничения. После достижения
лимита просмотр вакансий продолжается, но новые отклики откладываются до следующего дня.

Эквивалентный низкоуровневый параметр — `--auto-respond`. Перед откликом вакансия
должна пройти фильтры, получить оценку не ниже `match_threshold` и успешно пройти
содержательный просмотр. Затем приложение действует по принципу «не уверен — не
отправляй»:

1. проверяет признаки теста, обязательного письма и внешнего адреса;
2. один раз нажимает семантическую кнопку «Откликнуться»;
3. отправляет открытую форму только тогда, когда в ней нет обязательных полей;
4. считает отклик успешным лишь после видимого подтверждения HH;
5. при анкете, письме, выборе резюме, авторизации, редиректе или неизвестном исходе
   пропускает отклик на эту вакансию, записывает причину и продолжает со следующей;
6. не повторяет автоматически отклик с уже записанным результатом.

Первый исход по вакансии сохраняется в SQLite и защищает от повторного автоматического
отклика. Файл `.hh-resume-raiser/vacancy-responses.xlsx` пересобирается из этой истории.
В листе `Отклики` доступны стандартные фильтры Excel по статусу, причине ручного
действия, вакансии, компании, запросу и оценке соответствия. Файл можно открыть в
Microsoft Excel, LibreOffice Calc или другом редакторе XLSX. Если он открыт на запись,
SQLite всё равно сохранит результат, а журнал обновится после закрытия файла и
следующего отклика.

Если HH после нажатия показывает информационное окно с рекомендациями, его видимый
текст сохраняется в отдельной колонке `Сообщение HH после отклика`. Это помогает
разобрать статус `unknown`, но не превращает рекомендацию в автоматическое
подтверждение: повторный отклик по-прежнему не выполняется.

## Параметры командной строки

Полный актуальный список доступен через:

```text
task help
```

Основные параметры:

- `--resume-title` — точное название управляемого резюме;
- `--config-file` — путь к INI-файлу названия резюме и поисковых запросов;
- `--search-query` — запрос выдачи; можно повторить для нескольких вариантов;
- `--profile-dir` — каталог постоянного профиля Chromium;
- `--headless` — запуск без видимого окна;
- `--once` — завершение после одного цикла;
- `--dry-run` — чтение состояния без поднятия и дополнительных действий;
- `--credentials-file` — путь к локальному INI-файлу;
- `--check-login` — отдельная проверка входа во временном профиле;
- `--install-browser` — установка Chromium средствами Playwright;
- `--poll-seconds` — период сверки часов при обычном ожидании;
- `--page-refresh-seconds` — watchdog нераспознанного состояния страницы;
- `--buffer-seconds` — запас времени перед повторной проверкой поднятия;
- `--minimum-cooldown-hours` — минимальная локальная защита повторного нажатия;
- `--restart-browser-on-close` — явно разрешить перезапуск закрытого Chromium;
- `--full-activity` — включить выдачу, вакансии и проверку структуры резюме;
- `--activity-interval-seconds` — пауза после каждой группы, по умолчанию 300 секунд;
- `--vacancies-per-group` — желаемый максимум вакансий в группе, по умолчанию 5;
- `--vacancies-per-cycle` — обратный алиас предыдущего имени параметра;
- `--vacancy-matching` / `--no-vacancy-matching` — включить или отключить оценку;
- `--match-threshold` — минимальная оценка для автоматического отклика, 0–100;
- `--auto-respond` / `--no-auto-respond` — включить или явно выключить простые
  отклики без обязательных форм;
- `--daily-response-limit` — максимум успешных откликов за день, 0 отключает лимит;
- `--search-scrolls` — прокруток выдачи, допустимо 0–20;
- `--vacancy-scrolls` — прокруток одной вакансии, допустимо 0–10;
- `--scroll-pause-seconds` — пауза между прокрутками;
- `--vacancy-view-seconds` — время просмотра одной вакансии;
- `--resume-index-refresh` — включить обратимую смену версии описания опыта;
- `--resume-index-refresh-seconds` — интервал смены версии, по умолчанию 1800 секунд.

## Расписание и завершение работы

Следующее доступное поднятие определяется по наблюдаемому состоянию интерфейса HH.
Время повторно сравнивается с системными часами, поэтому сон или гибернация не
должны приводить к использованию устаревшего таймера. При неизвестном состоянии
страницы watchdog перезагружает её и повторяет чтение.

По умолчанию ручное закрытие окна Chromium немедленно завершает программу без
перезапуска. Автовосстановление включается только флагом
`--restart-browser-on-close`.

Для штатной остановки используйте Ctrl+C один раз и дождитесь сообщения
`Остановлено пользователем.`. Принудительное завершение может помешать Chromium
сохранить состояние профиля.

## Telegram-панель

Telegram-бот служит отдельной панелью управления и не запускает произвольные
команды. Он работает только с экземплярами, заранее перечисленными в `.env`, и
принимает команды только от разрешённых Telegram user ID.

Через панель можно:

- увидеть, работает ли выбранный экземпляр HHRaiser;
- вручную запустить или остановить его после дополнительного подтверждения;
- посмотреть последние строки системного журнала;
- получить сводную статистику из SQLite;
- получить PNG-дашборд с вкладом поисковых запросов, распределением оценки
  соответствия, исходами откликов и динамикой откликов за последние 14 дней;
- скачать актуальный Excel-журнал откликов;
- безопасно просматривать и менять разрешённые настройки выбранного экземпляра;
- восстановить предыдущую версию настроек и перезапустить работающий экземпляр;
- получить изображение текстовой CAPTCHA HH и вручную передать ответ браузеру;
- получать периодическую сводку по работающим экземплярам с интервалом
  `summary_interval_minutes`; остановленные экземпляры в рассылку не попадают, а
  значение `0` полностью отключает автоматические сообщения.

Токен и все настройки Telegram-панели хранятся в локальном `.env`: заполните
`HHRAISER_BOT_TOKEN`, `HHRAISER_BOT_ALLOWED_USER_IDS` и блок
`HHRAISER_INSTANCE_MAIN_*` из `.env.example`, затем выполните `task bot`. По
умолчанию эти переменные указывают на `state/main` в корне проекта, поэтому
дополнительно копировать `hh-config.ini` не нужно.
`hh-bot.ini` поддерживается только при явном запуске с `--config-file hh-bot.ini`.

Long polling не требует домена, HTTPS-сертификата или открытого входящего порта; с
одним токеном одновременно должен работать только один экземпляр бота.

Шаблоны служб находятся в `deploy/systemd/`, но пошаговая серверная установка,
платформенные команды и ручная настройка каталогов намеренно не приводятся в быстром
руководстве. Они будут заменены универсальным установщиком из
[плана установки](docs/installation-roadmap.md). До его появления сервер разворачивается
только по отдельной проверенной инструкции команды.

В Telegram откройте экземпляр и нажмите **⚙️ Настройки**. Бот показывает текущее
значение, принимает новое, проверяет его тип и диапазон, затем выводит сравнение
«было → станет». Запись выполняется только после отдельного подтверждения. Перед
заменой создаётся резервная копия в `config-backups`, а обезличенная запись об
изменённом поле добавляется в `config-audit.jsonl`. Токен Telegram, пароль HH и
профиль Chromium через это меню прочитать или изменить невозможно. Если экземпляр
уже работает, бот предложит подтвердить его перезапуск; иначе настройка применится
при следующем запуске.

### Ручное подтверждение CAPTCHA через Telegram

Если HH перенаправляет браузер на `/account/captcha`, HHRaiser распознаёт защитную
страницу до чтения названия вакансии и приостанавливает все действия. Бот присылает
только изображение CAPTCHA и просит ответить непосредственно на это сообщение.
Ответ привязан к одноразовому запросу: сообщения другого пользователя, ответы на
старую картинку и повторная отправка не принимаются.

Без `--telegram-captcha` в видимом режиме HHRaiser также не продолжает обход:
он оставляет CAPTCHA в окне Chromium и ждёт, пока владелец введёт ответ вручную.
В headless-режиме без Telegram это невозможно, поэтому процесс завершится с понятной
инструкцией запустить видимый режим или включить Telegram-подтверждение.

### Автоматическое решение капчи

Укажите `enabled = true` в `[captchasolution]`, чтобы `task full-activity` и
`task full-activity-ui` автоматически включали `CaptchaSolutione` в
`hh_raiser/infrastructure/browser/captcha_answer_source.py`. Источник берёт
`polza_api_key`, `ocr_prompt`, `api_url` и `model` из секции `[captchasolution]`
локального `hh-config.ini`, распознаёт изображение через Gemini и возвращает только
текст ответа.

При CAPTCHA в Telegram-режиме HHRaiser выполняет до пяти попыток Gemini. Каждый
ответ вводится в форму и проверяется HH. Только если все пять попыток не приняты
или модель не вернула текст, CAPTCHA сохраняется и отправляется владельцу в Telegram
для ручного ответа. Ошибки настройки или API не останавливают основную работу и
также переводят CAPTCHA в ручной режим.

Флаг `--captcha-answer-source` принудительно включает Gemini для одного запуска,
а `--no-captcha-answer-source` принудительно отключает его.

## Структура проекта

```text
hh_raiser/
├── activities/       # отдельные действия на HH
├── application/      # оркестрация и ротация вакансий
├── domain/           # состояния, результаты и политики
├── infrastructure/   # Playwright, локаторы и адаптеры браузера
├── reporting/        # обезличенный журнал активности
├── browser.py        # сессия, авторизация и чтение состояния
├── cli.py            # параметры и основной цикл
├── config.py         # пользовательские настройки профессии и запросов
├── scheduling.py     # расчёт времени и прерываемое ожидание
└── storage.py        # локальное состояние

docs/research/        # результаты исследования интерфейса HH
docs/adr/             # журнал архитектурных решений и их последствий
tests/                # модульные и компонентные тесты
Taskfile.yml          # единые команды установки, запуска и проверок
pyproject.toml        # метаданные и зависимости Python-проекта
uv.lock               # точные кроссплатформенные версии зависимостей
hh_resume_raiser.py   # совместимая точка запуска
```

## Архитектурные решения

Существенные решения фиксируются как ADR в [docs/adr](docs/adr/README.md). Запись
содержит контекст, рассмотренные альтернативы, принятое решение, формулы и известные
последствия. Новое решение не переписывает историю: оно добавляется отдельным ADR.

Исследовательские документы описывают наблюдаемые состояния, устойчивые локаторы,
подтверждение результата и неизвестные исходы для каждого автоматизированного
действия.

## Навыки агента

В `.agents/skills/` находятся проектные инструкции, автоматически применяемые при
работе с репозиторием:

- `conventional-commits` — Conventional Commits с русским описанием;
- `python-quality` — стандарты Python 3.12, архитектуры, Playwright, тестов и
  безопасного журналирования;
- `find-skills` — поиск и оценка дополнительных Skills через skills.sh;
- `python-patterns` — идиоматичный Python, PEP 8, типизация и структура пакетов;
- `python-code-style` — Ruff, mypy, именование, docstrings и документация;
- `clean-code-principles` — SOLID, DRY, KISS, YAGNI и шаблоны проектирования;
- `pytest-skill` — fixtures, parametrization, mocking и организация тестов;
- `async-python-patterns` — безопасная конкурентность и работа с `asyncio`;
- `python-performance-optimization` — профилирование и измеримая оптимизация;
- `code-review-excellence` — системное ревью логики, тестов и безопасности;
- `systematic-debugging` — поиск первопричины и воспроизводимая диагностика;
- `interactive-architecture-diagrams` — React Flow, ELK.js, правая панель,
  автономная сборка и обязательная визуальная проверка схем.

Skills хранятся вместе с кодом, поэтому одинаковые правила действуют для всех
последующих сессий и разработчиков, использующих совместимого агента. Версии и
источники внешних Skills зафиксированы в `skills-lock.json`.

## Проверка и разработка

```text
task check
```

Отдельные проверки и форматирование доступны как:

```text
task lint
task test
task format
```

Низкоуровневая точка входа остаётся доступна через
`uv run hh-resume-raiser`; совместимый файл `hh_resume_raiser.py` также сохранён.

## Частые проблемы

### После запуска нет новых сообщений

Программа может ожидать рассчитанное время следующего действия. Посмотрите строку
`Следующая проверка через ...`. В headless-режиме окно браузера не отображается.

### HH просит пароль, код или CAPTCHA

При запущенном Telegram-боте текстовая CAPTCHA появится в личном чате. Ответьте на
сообщение с изображением — основной процесс продолжит работу после подтверждения HH.
Если показана интерактивная CAPTCHA, код входа или другая неподдерживаемая проверка,
остановите фоновый запуск и выполните `task init-session`, затем снова запустите
основной режим.

### Playwright не находит Chromium

```text
task install-browser
```

### Профиль Chromium уже используется

Не запускайте одновременно два экземпляра с одним `--profile-dir`. Завершите
предыдущий процесс и убедитесь, что созданное им окно Chromium закрыто.

### Карточки или кнопка перестали распознаваться

Интерфейс HH.ru может измениться. Сохраните обезличенный фрагмент журнала и
проверьте документы в `docs/research/`; не заменяйте семантические локаторы
координатами или нестабильными CSS-классами.

## Безопасность и ограничения

Проект предназначен для личного использования владельцем резюме. Не используйте
его для массового сбора данных, обхода CAPTCHA, ограничений платформы или действий
от имени других пользователей. Перед включением откликов проверьте настройки поиска
и порог соответствия: функция выполняет реальное внешнее действие от вашего имени.

Владелец самостоятельно отвечает за соблюдение действующих правил HH.ru. Сайт
может менять интерфейс, доступность действий и ограничения без предварительного
уведомления. Статистика проекта описывает только наблюдаемые события и не является
доказательством изменения внутреннего ранжирования.
