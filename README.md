# HHRaiser

**Локальный менеджер активности и актуальности личного резюме на HH.ru**

![Python](https://img.shields.io/badge/Python-3.12%2B-3776AB?logo=python&logoColor=white)
![Playwright](https://img.shields.io/badge/Playwright-1.62%2B-2EAD33?logo=playwright&logoColor=white)
![Status](https://img.shields.io/badge/status-experimental-orange)

Разработка и сопровождение: [jmp-ff25](https://github.com/jmp-ff25)

</div>

HHRaiser автоматизирует разрешённые действия владельца личного резюме: проверяет
доступность поднятия, просматривает настраиваемую выдачу вакансий, контролирует структуру
резюме и ведёт обезличенный журнал активности. Приложение работает локально через
Playwright и постоянный профиль Chromium; архитектура разделена на доменный,
прикладной и инфраструктурный слои для дальнейшего переноса на сервер.

> Проект не отправляет отклики и не обещает повышения позиции резюме. Влияние
> наблюдаемых действий на внутренние алгоритмы HH.ru не считается доказанным.

## Быстрый старт

Ниже — одинаковый для Windows, Linux и macOS путь от клонирования до запуска
всех возможностей. Платформенные различия скрыты за Task и `uv`.

Один раз установите [uv](https://docs.astral.sh/uv/getting-started/installation/)
и [Task](https://taskfile.dev/docs/installation/). Если Node.js уже установлен,
Task можно поставить одинаковой на всех платформах командой
`npm install --global @go-task/cli`.

### 1. Установите проект

```text
git clone git@github.com:jmp-ff25/HHRaiser.git
cd HHRaiser
task install
```

Команда создаёт `.venv` через `uv`, устанавливает приложение и Chromium, а затем
копирует шаблон в `hh-config.ini`, только если локальной конфигурации ещё нет.

### 2. Укажите своё резюме и поисковые запросы

Откройте `hh-config.ini` и замените значения своими:

```ini
[resume]
title = Точное название моего резюме

[activity]
search_queries =
    Первый поисковый запрос
    Второй поисковый запрос
search_pages_per_cycle = 25
unique_vacancy_limit = 1000
revisit_after_days = 14
reset_on_exhaustion = true

[search_filters]
excluded_words =
    senior
    аналитик
    тестировщик
search_fields =
    name
experience =
    between1And3
    between3And6

[matching]
enabled = true
threshold = 65
```

### 3. Добавьте учётные данные

Создайте в корне проекта файл `hh-credentials.ini`:

```ini
[hh]
phone = +70000000000
password = replace-me
```

Оба локальных INI-файла исключены из Git.

### 4. Один раз инициализируйте сессию

```text
task init-session
```

Завершите вход, CAPTCHA или дополнительное подтверждение в открытом Chromium.

### 5. Запустите полный непрерывный режим

```text
task full-activity
```

Эта команда включает автоматическое поднятие, циклический просмотр настроенной
выдачи, предварительный отбор и просмотр подходящих вакансий, проверку структуры
резюме и обратимое обновление его версии.
Остановить программу можно одним нажатием Ctrl+C.

Профиль `full-activity` использует порог 65: к просмотру допускаются вакансии с расчётной
оценкой соответствия не ниже 65 из 100. Это объяснимая эвристическая оценка, а не
статистически подтверждённая вероятность успеха или трудоустройства.

Чтобы наблюдать работу визуально, используйте `task full-activity-ui`.

## Возможности

- поднятие выбранного резюме только тогда, когда соответствующее действие доступно;
- распознавание следующего времени поднятия и ожидание по системным часам;
- защита от повторного нажатия локальным cooldown-маркером;
- открытие выдачи и чередование заданных владельцем поисковых запросов;
- серверная фильтрация HH по словам-исключениям, областям поиска и опыту;
- перемешанный обход запросов и страниц выдачи без повторений в рамках прохода;
- постоянная SQLite-история обнаруженных и успешно просмотренных вакансий;
- глобальная дедупликация вакансий между разными поисковыми запросами;
- объяснимая оценка соответствия вакансии выбранному резюме до прокрутки;
- пропуск неподходящих вакансий без отметки об успешном просмотре;
- прокрутка выдачи и содержательный просмотр отдельных вакансий;
- отображение названия каждой открытой вакансии и итоговой сводки цикла в журнале;
- проверка наличия основных разделов резюме и рекомендаций HH;
- опциональная обратимая смена версии описания опыта с подтверждением сохранения;
- автоматическое закрытие известного рекламного окна hh PRO;
- видимый и headless-режимы, одноразовый запуск и непрерывная работа;
- корректная остановка при Ctrl+C или закрытии окна браузера;
- обезличенный JSONL-журнал для последующей аналитики.

Автоматическая отправка откликов принципиально не входит в проект.

## Команды Task

`Taskfile.yml` является единой оболочкой для локального запуска и CI. Одни и те же
команды используются в любом поддерживаемом терминале:

- `task install` — установить приложение и Chromium;
- `task init-session` — выполнить первичную авторизацию в видимом Chromium;
- `task raise` / `task raise-ui` — только поднятие в фоновом или видимом режиме;
- `task activity` / `task activity-ui` — поднятие и вакансии без смены версии резюме;
- `task full-activity` / `task full-activity-ui` — все возможности, включая
  обратимую смену версии резюме;
- `task activity-once` / `task full-activity-once` — один видимый цикл;
- `task check` — линтер и все тесты;
- `task build` — собрать wheel и исходный архив;
- `task` — показать весь список с краткими пояснениями.

Значения полного профиля можно переопределить без редактирования Taskfile:

```text
task full-activity MATCH_THRESHOLD=75 ACTIVITY_INTERVAL_SECONDS=600
```

Любые дополнительные параметры исходного CLI передаются после `--`:

```text
task full-activity -- --vacancies-per-cycle 5
```

Пути к локальным файлам также настраиваются переменными Task:

```text
task full-activity CONFIG_FILE=my-config.ini CREDENTIALS_FILE=my-credentials.ini
```

## Настройка профессии и запросов

Приложение не содержит встроенного названия профессии или резюме. Скопируйте
шаблон и укажите собственные значения:

```text
task prepare-config
```

```ini
[resume]
title = Точное название моего резюме

[activity]
search_queries =
    Первый поисковый запрос
    Второй вариант профессии
    Третий поисковый запрос
search_pages_per_cycle = 25
unique_vacancy_limit = 1000
revisit_after_days = 14
reset_on_exhaustion = true

[search_filters]
excluded_words =
search_fields =
experience =

[matching]
enabled = true
threshold = 55
```

`resume.title` должен точно совпадать с заголовком нужного резюме на HH.ru. В
`activity.search_queries` можно записать один или несколько запросов, по одному на
строку. Запросы и известные страницы выдачи перемешиваются без повторений в рамках
одного прохода. Остальные параметры управляют бюджетом поиска, размером цикла
уникальных просмотров и минимальным сроком до повторного просмотра. Локальный `hh-config.ini`
исключён из Git.

Путь можно изменить переменной Task `CONFIG_FILE`. Разовые значения можно передать
исходному CLI после `--`, не создавая INI-файл:

```text
task activity-ui -- --resume-title "Моё резюме" --search-query "Первый запрос" --search-query "Второй запрос"
```

Также поддерживаются `HH_RESUME_TITLE` и список `HH_SEARCH_QUERIES`, разделённый
символом `|`. Приоритет: CLI, переменные окружения, `hh-config.ini`.

## Поисковые фильтры HH

Секция `[search_filters]` применяется ко всем значениям `activity.search_queries`
и ко всем страницам пагинации. Она отсекает заведомо неподходящие результаты на
стороне поиска HH до открытия вакансии и локального расчёта совместимости.

Например, следующий набор ищет запрос только в названии вакансии, исключает
Senior- и смежные роли и оставляет вакансии с опытом от одного года до шести лет:

```ini
[search_filters]
excluded_words =
    senior
    team lead
    аналитик
    тестировщик
    tester
    test
    qa
    sdet
search_fields =
    name
experience =
    between1And3
    between3And6
```

Допустимые `search_fields`:

- `name` — название вакансии;
- `company_name` — название компании;
- `description` — описание вакансии.

Допустимые уровни `experience`:

- `noExperience` — нет опыта;
- `between1And3` — от одного года до трёх лет;
- `between3And6` — от трёх до шести лет;
- `moreThan6` — более шести лет.

Значения записываются по одному на строку. Пустой параметр не создаёт ограничение и
сохраняет стандартное поведение HH. Произвольные query-параметры не принимаются:
разрешённый список защищает конфигурацию от опечаток и устаревших параметров.

Фильтры дополняют локальное сопоставление, а не заменяют его: сначала HH уменьшает
шум в выдаче, затем математический алгоритм анализирует полное описание. Результаты
исследования находятся в [документе о фильтрах](docs/research/search-filters.md), а
архитектурное решение — в [ADR-0002](docs/adr/0002-allowlisted-search-filters.md).

## Сопоставление вакансии с резюме

До прокрутки вакансии приложение читает доступные в DOM заголовок, описание и теги
навыков. Текст выбранного резюме читается только в память процесса и не сохраняется.
Затем рассчитывается объяснимая оценка от 0 до 100 на основе четырёх признаков:

- сходство названий по коэффициенту Дайса;
- BM25F-подобная релевантность с повышенным весом названия и тегов навыков;
- доля навыков вакансии, найденных в резюме;
- косинусная близость частотных векторов значимых терминов.

Признаки объединяются логистической функцией. При оценке ниже `matching.threshold`
страница не прокручивается и не считается просмотренной. Решение сохраняется по
публичному ID, чтобы не анализировать ту же вакансию повторно в текущем цикле.

Начальные коэффициенты являются инженерной политикой, поэтому число называется
расчётной оценкой совместимости, а не подтверждённой вероятностью. Персональная
калибровка станет возможна после накопления явных пользовательских отметок.

```ini
[matching]
enabled = true
threshold = 55
```

Фильтр можно временно отключить через `--no-vacancy-matching`, а порог заменить
через `--match-threshold 65`. Полное обоснование и формулы находятся в
[ADR-0001](docs/adr/0001-explainable-vacancy-matching.md).

## Алгоритм уникального просмотра вакансий

При первом обращении к поисковому запросу приложение открывает его первую страницу,
чтобы определить наблюдаемое количество страниц пагинации. Затем применяется
вариант алгоритма *shuffle bag*: запросы и ещё не проверенные страницы выбираются в
случайном порядке без возвращения. Это не позволяет случайности постоянно выбирать
одну и ту же страницу.

HH не предоставляет приложению отдельный признак «уникальные вакансии закончились».
Для каждого запроса приложение запоминает наблюдаемое число страниц пагинации и
номера уже проверенных страниц. Запрос считается исчерпанным в текущем проходе,
когда все эти страницы проверены, а найденные ссылки уже оценивались, просматривались
или временно недоступны по истории. Новый логический проход начинается после
исчерпания страниц всех настроенных запросов, а не одного из них.

На каждой странице приложение собирает канонические ссылки и извлекает публичный
идентификатор вакансии. SQLite-история является глобальной: вакансия, найденная по
двум разным запросам, всё равно считается одной вакансией. Кандидаты временно
резервируются короткой транзакцией, что закладывает основу для последующего запуска
нескольких обработчиков с общей базой.

За цикл проверяется до `search_pages_per_cycle` страниц, пока не будет набрано
`vacancies_per_cycle` прошедших локальную проверку кандидатов. Статус просмотренной
записывается только после успешного распознавания открытой страницы. Ошибка,
закрытие страницы или `unknown outcome` освобождает резерв и не исключает вакансию
из будущих попыток.

История не удаляется физически. После `unique_vacancy_limit` успешных уникальных
просмотров либо полного прохода известных страниц, если `reset_on_exhaustion =
true`, начинается новый логический цикл уникальных просмотров. Лимит и история
действуют глобально для всех запросов, а не отдельно для каждого поискового запроса.
Старые записи снова могут участвовать в выборе только после `revisit_after_days`.
Поэтому программа продолжит работу и новые вакансии по-прежнему будут доступны,
но до появления новых объявлений или истечения этого срока отдельный цикл может
завершиться без содержательных просмотров. История при этом не удаляется.

Вручную начать новый цикл уникальных просмотров и сразу запустить полный режим можно
готовой задачей:

```text
task full-activity-reset-history
```

## Интерактивная схема бизнес-логики

Основная [интерактивная карта архитектуры](docs/architecture-viewer/index.html)
показывает жизненный цикл приложения, отбор вакансий, исключение повторных
просмотров и границы компонентов. Нажатие на любой элемент открывает постоянную
панель с ответственностью, предусловиями, успешным и неизвестным исходами,
настройками и ссылками на соответствующий код или ADR.

Карта построена на React Flow и автоматически раскладывается ELK.js слева направо.
Доступны поиск, масштабирование, мини-карта, светлая и тёмная темы, четыре уровня
детализации и ссылки на выбранный элемент в URL. Production-сборка содержит все
зависимости внутри одного HTML-файла, не использует CDN и работает без интернета.
Откройте `docs/architecture-viewer/index.html` любым современным браузером.

Node.js и локальный веб-сервер для обычного просмотра не требуются. Адрес вида
`http://127.0.0.1:5173` появляется только в режиме разработки, когда изменения
исходников нужно видеть сразу после сохранения. Такой процесс работает, пока открыт
запустивший его терминал, и останавливается сочетанием `Ctrl+C`.

Для изменения карты сначала установите её зависимости, затем запустите режим
разработки:

```text
task diagram-install
task diagram-dev
```

После запуска `task diagram-dev` откройте адрес, который Vite напечатает в
терминале. Этот режим необязателен и предназначен только для разработки карты.

После изменений проверьте модель и пересоберите автономный файл:

```text
task diagram-check
```

Предыдущая [интерактивная блок-схема](docs/business-logic.html) сохранена для
сравнения. Для разработчиков также доступны две компактные схемы PlantUML:
[обзор непрерывного цикла](docs/diagrams/overview.svg) и
[детальный отбор вакансий](docs/diagrams/vacancy-flow.svg). Исходники PlantUML
находятся рядом в каталоге `docs/diagrams`.

установки зависит от терминала, поэтому для локального запуска рекомендуется
одинаковый на всех платформах файл `hh-credentials.ini`.

Приоритет источников: параметры командной строки, переменные окружения, INI-файл,
интерактивный ввод. Передавать пароль прямо в командной строке нежелательно: он
может сохраниться в истории терминала или отображаться в списке процессов.

## Первичная авторизация

Перед первым headless-запуском, после смены пароля или при появлении CAPTCHA
инициализируйте постоянную сессию в видимом Chromium:

```text
task init-session
```

Завершите вход, CAPTCHA или дополнительное подтверждение в открытом окне. Когда
программа попросит, нажмите Enter в терминале. `--dry-run` запрещает поднятие и
дополнительные действия, но авторизованная сессия сохраняется в локальном профиле.

Проверить авторизацию без использования основного профиля можно так:

```text
task check-login
```

## Режимы запуска

### Только автоматическое поднятие резюме

Непрерывный headless-режим без индекса активности:

```text
task raise
```

Для видимого Chromium используйте `task raise-ui`; окно автоматически развернётся
по доступной области монитора.

### Однократная безопасная проверка

```text
task init-session
```

### Один полный цикл просмотра

```text
task activity-once
```

### Непрерывное поднятие и просмотр вакансий

```text
task activity
```

`--vacancies-per-cycle` ограничивает только один цикл. Пока программа работает,
общее количество циклов и просмотренных вакансий не ограничено.

### Полный режим с обратимым обновлением версии резюме

```text
task full-activity
```

Этот режим выключен по умолчанию. Первый цикл выполняется сразу: приложение
последовательно выбирает опыт и добавляет одну контрольную точку. На следующем
цикле точка удаляется из того же опыта, сохранение подтверждается повторным чтением
интерфейса, после чего выбирается следующий опыт. Содержимое описания не хранится
в служебных файлах — сохраняются только номер опыта, исходное число конечных точек
и контрольная сумма нормализованного текста.

## Параметры командной строки

Полный актуальный список доступен через:

```text
task help
```

Основные параметры:

- `--resume-title` — точное название управляемого резюме;
- `--config-file` — путь к INI-файлу названия резюме и поисковых запросов;
- `--search-query` — запрос выдачи; можно повторить для нескольких вариантов;
- `--profile-dir` — каталог постоянного профиля Chromium;
- `--headless` — запуск без видимого окна;
- `--once` — завершение после одного цикла;
- `--dry-run` — чтение состояния без поднятия и дополнительных действий;
- `--credentials-file` — путь к локальному INI-файлу;
- `--check-login` — отдельная проверка входа во временном профиле;
- `--install-browser` — установка Chromium средствами Playwright;
- `--poll-seconds` — период сверки часов при обычном ожидании;
- `--page-refresh-seconds` — watchdog нераспознанного состояния страницы;
- `--buffer-seconds` — запас времени перед повторной проверкой поднятия;
- `--minimum-cooldown-hours` — минимальная локальная защита повторного нажатия;
- `--restart-browser-on-close` — явно разрешить перезапуск закрытого Chromium;
- `--full-activity` — включить выдачу, вакансии и проверку структуры резюме;
- `--activity-interval-seconds` — интервал полных циклов, по умолчанию 300 секунд;
- `--vacancies-per-cycle` — вакансий за цикл, по умолчанию 10, допустимо 0–25;
- `--search-pages-per-cycle` — максимум страниц для поиска новых вакансий за цикл;
- `--unique-vacancy-limit` — размер цикла уникальных просмотров, 0 отключает лимит;
- `--revisit-after-days` — минимальный срок до повторного просмотра вакансии;
- `--reset-on-exhaustion` / `--no-reset-on-exhaustion` — автоматическое начало
  нового цикла после полного прохода;
- `--reset-vacancy-history` — вручную начать новый цикл уникальных просмотров;
- `--vacancy-matching` / `--no-vacancy-matching` — включить или отключить отбор;
- `--match-threshold` — минимальная оценка для содержательного просмотра, 0–100;
- `--search-scrolls` — прокруток выдачи, допустимо 0–20;
- `--vacancy-scrolls` — прокруток одной вакансии, допустимо 0–10;
- `--scroll-pause-seconds` — пауза между прокрутками;
- `--vacancy-view-seconds` — время просмотра одной вакансии;
- `--resume-index-refresh` — включить обратимую смену версии описания опыта;
- `--resume-index-refresh-seconds` — интервал смены версии, по умолчанию 1800 секунд.

## Расписание и завершение работы

Следующее доступное поднятие определяется по наблюдаемому состоянию интерфейса HH.
Время повторно сравнивается с системными часами, поэтому сон или гибернация не
должны приводить к использованию устаревшего таймера. При неизвестном состоянии
страницы watchdog перезагружает её и повторяет чтение.

По умолчанию ручное закрытие окна Chromium немедленно завершает программу без
перезапуска. Автовосстановление включается только флагом
`--restart-browser-on-close`.

Для штатной остановки используйте Ctrl+C один раз и дождитесь сообщения
`Остановлено пользователем.`. Принудительное завершение может помешать Chromium
сохранить состояние профиля.

## Логи и локальные данные

Консольный журнал содержит относительный путь и номер строки вызова:

```text
2026-09-09 17:42:40 INFO hh_raiser/activities/vacancy_viewer.py:54 Просматриваю вакансию 1 из 10: «Название вакансии».
```

После просмотра выводится одна сводка вместо повторяющихся сообщений:

```text
Итоги просмотра вакансий: успешно — 10; неизвестный результат — 0; ошибки — 0; пропущено — 0.
```

Локальное состояние размещается в `.hh-resume-raiser/`:

- `browser-profile/` — профиль Chromium и авторизованная сессия;
- `activity-events.jsonl` — обезличенные результаты действий для аналитики;
- `vacancy-history.sqlite3` — локальная история ID, запросов, оценок, решений,
  циклов и просмотров;
- `status.json` — известное время следующего поднятия;
- служебные маркеры cooldown и обратимого обновления версии.

Каталог, INI-файл, cookies, профили, traces и исследовательские артефакты исключены
из Git. В JSONL-отчёт не записываются URL вакансий, query-параметры, cookies,
заголовки авторизации, пароли или содержимое резюме.

## Архитектурные решения

Существенные решения фиксируются как ADR в [docs/adr](docs/adr/README.md). Запись
содержит контекст, рассмотренные альтернативы, принятое решение, формулы и известные
последствия. Новое решение не переписывает историю: оно добавляется отдельным ADR.

Исследовательские документы описывают наблюдаемые состояния, устойчивые локаторы,
подтверждение результата и неизвестные исходы для каждого автоматизированного
действия.

## Навыки агента

В `.agents/skills/` находятся проектные инструкции, автоматически применяемые при
работе с репозиторием:

- `conventional-commits` — Conventional Commits с русским описанием;
- `python-quality` — стандарты Python 3.12, архитектуры, Playwright, тестов и
  безопасного журналирования;
- `find-skills` — поиск и оценка дополнительных Skills через skills.sh;
- `python-patterns` — идиоматичный Python, PEP 8, типизация и структура пакетов;
- `python-code-style` — Ruff, mypy, именование, docstrings и документация;
- `clean-code-principles` — SOLID, DRY, KISS, YAGNI и шаблоны проектирования;
- `pytest-skill` — fixtures, parametrization, mocking и организация тестов;
- `async-python-patterns` — безопасная конкурентность и работа с `asyncio`;
- `python-performance-optimization` — профилирование и измеримая оптимизация;
- `code-review-excellence` — системное ревью логики, тестов и безопасности;
- `systematic-debugging` — поиск первопричины и воспроизводимая диагностика;
- `interactive-architecture-diagrams` — React Flow, ELK.js, правая панель,
  автономная сборка и обязательная визуальная проверка схем.

Skills хранятся вместе с кодом, поэтому одинаковые правила действуют для всех
последующих сессий и разработчиков, использующих совместимого агента. Версии и
источники внешних Skills зафиксированы в `skills-lock.json`.

## Частые проблемы

### После запуска нет новых сообщений

Программа может ожидать рассчитанное время следующего действия. Посмотрите строку
`Следующая проверка через ...`. В headless-режиме окно браузера не отображается.

### HH просит пароль, код или CAPTCHA

Остановите фоновый запуск и выполните `task init-session`. После успешного
подтверждения снова запустите основной режим.

### Playwright не находит Chromium

```text
task install-browser
```

### Профиль Chromium уже используется

Не запускайте одновременно два экземпляра с одним `--profile-dir`. Завершите
предыдущий процесс и убедитесь, что созданное им окно Chromium закрыто.

### Карточки или кнопка перестали распознаваться

Интерфейс HH.ru может измениться. Сохраните обезличенный фрагмент журнала и
проверьте документы в `docs/research/`; не заменяйте семантические локаторы
координатами или нестабильными CSS-классами.

## Безопасность и ограничения

Проект предназначен для личного использования владельцем резюме. Не используйте
его для массового сбора данных, автоматической отправки откликов, обхода CAPTCHA,
ограничений платформы или действий от имени других пользователей.

Владелец самостоятельно отвечает за соблюдение действующих правил HH.ru. Сайт
может менять интерфейс, доступность действий и ограничения без предварительного
уведомления. Статистика проекта описывает только наблюдаемые события и не является
доказательством изменения внутреннего ранжирования.
