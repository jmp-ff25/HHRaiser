# ADR-0004: безопасные отклики и журнал результатов

- Статус: принято
- Дата: 2026-09-11

## Контекст

Владелец хочет откликаться на уже отобранные и просмотренные вакансии, но не передавать
автоматике ответы на вопросы работодателя, тесты, сопроводительные письма и внешние
формы. Ошибочное повторное нажатие опаснее пропущенного отклика: интерфейс мог принять
первую отправку, даже если подтверждение не удалось прочитать.

## Решение

Отклики выключены по умолчанию и включаются только настройкой `responses.enabled` или
параметром `--auto-respond`. Сценарий запускается после успешного просмотра вакансии,
прошедшей порог соответствия.

Публичные признаки HH используются только для предварительной остановки. Основным
подтверждением успеха остаётся видимое состояние интерфейса. Кнопка нажимается не более
одного раза на каждом шаге. Обнаруженная анкета, тест, обязательное письмо, выбор резюме,
авторизация, внешний адрес или неизвестный результат завершают только попытку отклика
на текущую вакансию. Общий цикл продолжает обработку следующей вакансии.

Первый исход сохраняется по публичному ID вакансии в SQLite. Автоматических повторов для
этого ID нет даже после нового цикла уникальных просмотров. XLSX является удобным
фильтруемым представлением SQLite-истории, а не самостоятельным источником данных.

## Рассмотренные варианты

- Заполнять все формы автоматически — отклонено: ответы и письма требуют решения автора.
- Считать переход после клика успехом — отклонено: навигация не доказывает отправку.
- Повторять действие при неизвестном исходе — отклонено: возможен дублирующий отклик.
- Хранить только Excel — отклонено: открытый редактор может временно блокировать файл.

## Последствия

- Простые отклики выполняются без ручной работы, но сложные случаи видны в журнале.
- Часть допустимых откликов может быть консервативно пропущена при изменении интерфейса.
- Новые варианты форм HH требуют отдельного исследования и теста перед автоматизацией.
- SQLite сохраняет результат даже тогда, когда XLSX временно открыт в Excel.
