# ADR-0005: справедливый и сохраняемый поиск вакансий

- Статус: заменено ADR-0006
- Дата: 2026-09-15

## Контекст

Первоначальная ротация перемешивала запросы и страницы без повторов, но первая
результативная страница могла сразу заполнить все десять мест цикла. Поэтому один
широкий запрос часто определял весь видимый результат цикла, хотя остальные запросы
тоже выполнялись позднее. Номера исследованных страниц хранились только в памяти и
терялись после перезапуска. Равновероятный выбор глубокой страницы также не отдавал
предпочтение свежей части выдачи.

Логи показывали названия вакансий, но не объясняли, какой запрос и какая страница их
дали, сколько ссылок оказалось действительно новыми и сколько было исключено
историей. Из-за этого фактическое разнообразие нельзя было проверить по журналу.

## Решение

1. В каждом цикле целевые просмотры равномерно распределяются между настроенными
   запросами. Остаток выдаётся случайным запросам, а не всегда первому в INI.
2. Неиспользованная квота узкого или исчерпанного запроса может быть заимствована
   другими запросами, чтобы не уменьшать общий полезный результат.
3. Первая страница каждого запроса проверяется один раз в каждом цикле как источник
   наиболее свежих результатов.
4. Глубокие непроверенные страницы выбираются случайно без возвращения, но их вес
   уменьшается с номером страницы.
5. Покрытие страниц текущего логического цикла сохраняется в SQLite и
   восстанавливается после перезапуска.
6. История вакансий остаётся глобальной: один публичный ID не становится новым из-за
   того, что встретился по другому запросу.
7. Для каждой страницы журнал фиксирует запрос, номер страницы, количество найденных,
   впервые обнаруженных, допустимых по истории и отобранных вакансий.

## Почему не выбран полностью адаптивный алгоритм

Многорукий бандит или автоматическое изменение весов по числу откликов мог бы чаще
использовать результативные запросы, но быстро вытеснил бы узкие варианты и сделал
решение труднее объяснимым. Текущий подход гарантирует минимальное разнообразие,
остаётся детерминированно проверяемым и одновременно позволяет занимать свободные
места более продуктивным запросам.

Накопленные показатели можно позднее использовать для отдельного, явно включаемого
адаптивного режима.

## Последствия

- один широкий запрос больше не должен занимать все места обычного цикла;
- свежая часть каждой выдачи проверяется регулярно;
- перезапуск не уничтожает прогресс исследования глубоких страниц;
- миграция добавляет таблицу `search_page_coverage`, не удаляя существующую историю;
- первая страница создаёт преднамеренный дополнительный сетевой запрос в каждом
  цикле;
- при `revisit_after_days = 0` начало нового логического цикла по-прежнему разрешает
  немедленные повторные просмотры — это явная пользовательская настройка, а не
  свойство планировщика.
