# ADR-0002: разрешённый список поисковых фильтров HH

- Статус: принято
- Дата: 2026-09-10

## Контекст

Один текстовый запрос может находить вакансии, где искомая технология упомянута
только как вспомогательная, а также неподходящие уровни позиции. HH предоставляет
серверные фильтры, которые сокращают такой шум до загрузки карточек и локальной
оценки совместимости.

## Решение

Ввести секцию `[search_filters]` с тремя проверенными настройками:

- `excluded_words` — слова и фразы, передаваемые как `excluded_text`;
- `search_fields` — повторяемые области `search_field`;
- `experience` — повторяемые уровни `experience`.

Приложение принимает только наблюдаемые значения областей и опыта. URL собирается
через стандартное percent-encoding; произвольные параметры из INI не допускаются.
Один экземпляр фильтров применяется ко всем пользовательским `search_queries` и ко
всем страницам их выдачи.

Пустая настройка означает отсутствие ограничения и сохраняет прежнее поведение.
Порядок отбора:

1. HH применяет серверные поисковые фильтры.
2. Локальная история исключает уже обработанные вакансии.
3. Локальный объяснимый matcher оценивает полное содержимое оставшихся вакансий.
4. Только прошедшая порог вакансия прокручивается и отмечается просмотренной.

## Рассмотренные альтернативы

### Автоматически нажимать элементы панели фильтров

Отклонено: это медленнее, зависит от состояния модального окна и создаёт больше
хрупких точек синхронизации. GET-параметры подтверждены самим интерфейсом HH и
воспроизводят наблюдаемое состояние.

### Разрешить произвольные query-параметры в INI

Отклонено: опечатки и устаревшие или чувствительные параметры нельзя надёжно
валидировать. Новые фильтры будут добавляться в типизированный разрешённый список
после отдельного наблюдения.

## Последствия

- Неподходящие вакансии отсекаются до открытия их страниц.
- Конфигурация не зависит от профессии владельца.
- Ошибка в имени enum обнаруживается при запуске, а не во время браузерного цикла.
- Для разных наборов фильтров по отдельным запросам в будущем понадобится расширить
  формат конфигурации; текущая версия сознательно использует один понятный набор.
